# QIMA — FRONTEND IMPLEMENTATION BRIEF

Implement the prototype as a guided validation demo, not as a production application.

## First screen
1. QIMA logo/name
2. "Prototype Demo"
3. One-sentence explanation
4. "Mulai Demo"

## Main flow
Welcome → Role → Scenario → Dashboard → Detail → Feedback.

## Required scenarios
- Santri Baru
- Kehadiran
- Progres
- Agenda

## Required roles
- Pengelola
- Admin
- Guru
- Orang Tua/Santri

## Interaction rules
- All primary CTAs should work.
- Use mock data only.
- Provide a Reset Demo action.
- Preserve a clear Back/Next path in guided mode.
- Never imply that data is real.
- Add a persistent "Prototype" label.

## Demo mode
A presenter should be able to complete the main journey in under 5 minutes.

## Success criterion
A person unfamiliar with QIMA should understand:
1. what QIMA is;
2. who it is for;
3. what workflow it helps organize;
4. what is prototype vs real;
5. where to give feedback.

Do not add backend or database in this phase.
